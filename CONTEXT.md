# AllOnFire

A personal monorepo holding a family of small products that share one user base,
one database, and one design system.

## Language

**App**:
One product in the monorepo, with its own users. Laura is the first App (paused
while the Design system is rebuilt); the Back Office is the internal one, and a
React Native client is planned. Who is allowed into an App is decided by their
Membership in it and the lowest Role the App lets in, including for internal
ones.
_Avoid_: site, project, product

**Back Office**:
The internal App where the family's content, users and data are managed. Only
admins enter it.
_Avoid_: dashboard, admin panel, console — Laura's `(dashboard)` is only a
route-group name, not this App.

**Section**:
An area of an App reached from its main menu. The Back Office's are Home,
Users and Storage; Home is the one a User lands on after Sign in.
_Avoid_: page (a page is a route, and a Section can hold several), tab, module

**App switcher**:
The menu at the top of an App's main menu that names the App you are in and
lists the other Apps you are allowed into, each a link to that App.
_Avoid_: team switcher, workspace switcher

**Design system**:
Everything an App draws its interface from: shadcn components, AOF components,
and the Designs. Apps reach shadcn only through AOF components, never
directly.
_Avoid_: UI kit, component library

**shadcn component**:
A component generated by the shadcn CLI and kept exactly as generated. Changed
only by regenerating it, never by hand.
_Avoid_: base component, primitive

**AOF**:
The prefix on anything AllOnFire wraps, always uppercase and in front of the
original name: an AOF component, or a piece of App scaffolding.

**AOF component**:
An AllOnFire component composed from shadcn components. The only place the
Design system is customised, and the only Design system component an App imports.
_Avoid_: custom component, wrapper

**AOF form**:
A form whose fields `useAOFForm` manages: checked in the browser, then sent to
a server action, which has the last word. A form without fields is not one.
_Avoid_: form kit, form library

**App scaffolding**:
The shared wiring every App composes piece by piece: providers, request config,
proxy and Next config. Not part of the Design system; an App keeps only the
pieces it needs.
_Avoid_: boilerplate, starter, kit

**Design**:
A named visual world, its rules and its tokens, that one or more Apps wear.
Japan is the first. Each App wears exactly one; a change to a Design reaches
every App wearing it.
_Avoid_: theme, skin, look, palette

**Brand**:
The AOF monogram, its O lit by a flame, on a dark ground. Every App's logo is
the Brand plus a banner in the App's own color carrying its name; the Brand is
shared by every App whatever Design it wears.
_Avoid_: logo (an App's logo is the Brand plus its banner)

**Indexing**:
Whether search engines may list an App's pages: indexed (listed, with its
language alternates and a sitemap) or unindexed (kept out; link previews still
work). Each App declares it among its settings.
_Avoid_: visibility, public/private (an Image's), SEO mode

**Offline page**:
The page an App shows, in the visitor's language, when a page cannot load
because there is no network. It is shown at the address that failed, and
retrying reloads that address. Losing the network in the middle of using an
App does not show it: the App waits and carries on once the connection
returns.
_Avoid_: offline screen, fallback page, error page (an error is the App's,
not the network's)

**Install hint**:
The dismissible card offering to install an App: an Install button where
the browser has its own install dialog, else the browser's steps (iPhone,
macOS Safari). Never on a first visit, never once installed; once dismissed
it stays away for a year on that device.
_Avoid_: install prompt (the browser's own dialog, which the hint's Install
button opens), install banner

**Image**:
A picture in one or more Apps, stored once. It is public, shown to anyone
even when not signed in, or private, shown only to those who enter at least
one of its Apps; that is the Image's own, never set per App. An App's Admin
adds it to their App or removes it from there; making it public or private,
which every one of its Apps shows, takes the Admin Role in every App it is
in. It is deleted when it is in no App any more, or by someone with the
Admin Role in every App it is in. It carries its alt text in the Base languages and, optionally, the other Content
languages. App content that shows a picture points to an Image rather than
holding the picture itself.
_Avoid_: media, asset, file, picture, photo

**Avatar**:
A User's own picture, shown beside their name in every App. It belongs to
the User, not to an App, so it is not an Image: it has no alt text of its own
and no placements. It is listed nowhere: its address reaches only those an
App shows the User to, but anyone holding that address sees it. A User has
at most one, set by an Admin or taken from the account they registered
with (Google's own picture); without one, their initial stands in.
_Avoid_: profile picture, profile image, photo

**Host**:
Anything deployed from the monorepo that composes the shared packages: every
App, and the API. A Host mounts modules and speaks its own languages; a second
backend or another frontend would be a Host too.
_Avoid_: app (for the API), consumer, runtime

**API**:
The standalone HTTP backend that serves every App. A Host, not an App: nobody
enters it.
_Avoid_: server, backend, service — "server" also means Next's Server
Components.

**Auth module**:
The shared package that owns signing in, Sessions and the access mechanism;
each App decides who is allowed in. Any Host mounts it; the API is the only one that does today.
_Avoid_: auth service, auth server

**Storage**:
Where the files behind App content live, kept apart from the database: Images
today, any other kind of file later. Which provider holds them (MinIO today)
is a detail only Storage knows.
_Avoid_: MinIO, bucket, S3 (for the concept), media library

**User module**:
The part of the Auth module that lists, adds and deletes Users. Any Host
mounts it and says who may list them and who may change them; the API lets in
only Back Office Admins. Nobody can delete themselves through it.
_Avoid_: Users module, user service, user admin

**Image module**:
The shared package that stores, lists, edits and deletes Images. Any Host
mounts it and decides how its errors read; the API is the only one that does
today.
_Avoid_: Images module, media service, upload service

**Base languages**:
English and Italian: every Host speaks them, and every text and alt has them.
A Host can speak more, and then translates everything it shows into each of
them, shared texts included.
_Avoid_: default languages, core languages

**Content languages**:
The Base languages plus every extra language any Host speaks. Stored texts such
as an Image's alt can hold any of them; only the Base languages are required.
_Avoid_: locales (a locale is a regional variant of a language)

**Session**:
Proof that a User signed in, held by the API. A browser carries it as a cookie.
_Avoid_: token, login

**Sign in** / **Sign out**:
Starting and ending a Session. Two words as verbs, `sign-in` / `sign-out` in
paths, keys and file names, `signIn` / `SIGN_IN` in code — the names Better
Auth uses for its own routes.
_Avoid_: log in, log out, login, logout

**User**:
A person with one account in the shared user base, whatever Apps they belong
to. A User with no Membership left still exists and is still listed.
Deleting a User removes them from every App at once, with everything they
hold there, and cannot be undone; removing them from one App ends a
Membership and leaves the User.
_Avoid_: account, member, customer

**Membership**:
A User's place in one App, with their Role there. A User holds one per App
they belong to; nothing spans every App.
_Avoid_: Allowed apps, permissions, entitlements, account

**Registration**:
Becoming a User through an App that allows it, which gives a Membership in that
App only. An existing User joins another such App the same way, once signed in.
Each App says whether it allows it; the Back Office never does. A User an
Admin adds by hand did not register: they were added, with the Memberships the
Admin chose.
_Avoid_: sign-up (except in Better Auth's route names), enrolment, invite

**Role**:
What a User may do inside one App: Admin, User or Viewer. It belongs to a
Membership, never to the User as a whole. The Role named User is always
written as a Role ("the User Role"), never as the person.
_Avoid_: permission level, rank

**Viewer**:
A Role in an App that allows browsing and playing but no mutations.
_Avoid_: guest, demo user, read-only user

**App schema**:
The Postgres schema holding one App's tables, named after the App (`laura`).
`auth` is the one schema no App owns: it holds the user base every App shares.
_Avoid_: "schema" alone — it also means the Prisma schema files and zod
schemas; namespace

### Environments

**Local**:
The stack running on a developer machine: `docker-compose.dev.yml` services
plus the Apps and API running on the host.
_Avoid_: dev environment — `dev` is an integration branch, not a place anything
runs.

**Production**:
The VPS. The only deployed environment; the `test` and `prod` branches are
promotion gates, not environments.
_Avoid_: prod server, staging — no staging exists.

**Test database**:
A database made for one test run from the Fixtures and dropped when the run
ends. Never the Local database.
_Avoid_: test DB, dev database (for this).

**Fixture**:
A known User or Image every Test database holds, so a test can sign in with it
or point at it without creating it. Local holds none: it holds what Production
holds.
_Avoid_: mock user, seed user, test data.

**Deploy unit**:
One thing Production runs that ships on its own: the API, an App, or the
database migration. A change deploys exactly the units it affects, through
the packages they read.
_Avoid_: service (the compose word), release.

### Data about usage

**Telemetry**:
Traces, logs and metrics describing how the API behaves.
_Avoid_: monitoring, APM

**Analytics**:
Events describing what people do in an App.
_Avoid_: tracking, telemetry

**Workflow**:
An automation that runs outside the Apps and the API, on a schedule or when
something happens.
_Avoid_: n8n, job, cron (for the concept)
