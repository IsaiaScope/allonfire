# AllOnFire

A personal monorepo holding a family of small products that share one user base,
one database, and one design system.

## Language

**App**:
One product in the monorepo, with its own users. Laura is the first App (paused
while the Design system is rebuilt); the Back office is the internal one, and a
React Native client is planned. Who may enter an App is decided by Allowed apps,
including for internal ones.
_Avoid_: site, project, product

**Back office**:
The internal App where the family's content, users and data are managed. Only
admins enter it.
_Avoid_: dashboard, admin panel, console — Laura's `(dashboard)` is only a
route-group name, not this App.

**Design system**:
Everything an App draws its interface from: shadcn components, AOF components
and one Theme per App. Apps reach it through AOF components only.
_Avoid_: UI kit, component library

**shadcn component**:
A component generated by the shadcn CLI and kept exactly as generated. Changed
only by regenerating it, never by hand.
_Avoid_: base component, primitive

**AOF component**:
An AllOnFire component composed from shadcn components. The only place the
Design system is customised, and the only kind of component an App imports.
_Avoid_: custom component, wrapper

**Theme**:
One App's set of design tokens on top of the shared Design system. Each App has
exactly one.
_Avoid_: skin, palette

**API**:
The standalone HTTP backend that serves every App.
_Avoid_: server, backend, service — "server" also means Next's Server
Components.

**Auth module**:
The shared package that owns signing in, Sessions and the access rules. Any
backend mounts it; the API is the only one that does today.
_Avoid_: auth service, auth server

**Session**:
Proof that a User signed in, held by the API. A browser carries it as a cookie.
_Avoid_: token, login

**Sign in** / **Sign out**:
Starting and ending a Session. Two words as verbs, `sign-in` / `sign-out` in
paths, keys and file names, `signIn` / `SIGN_IN` in code — the names Better
Auth uses for its own routes.
_Avoid_: log in, log out, login, logout

**Viewer**:
A User whose Role allows browsing and playing but no mutations.
_Avoid_: guest, demo user, read-only user

**Allowed apps**:
The list on a User naming which Apps they may enter. The value `ALL` grants
every App.
_Avoid_: permissions, entitlements

**App schema**:
The Postgres schema holding one App's tables, named after the App (`laura`).
`auth` is the one schema no App owns: it holds the user base every App shares.
_Avoid_: "schema" alone — it also means the Prisma schema files and zod
schemas; namespace

### Environments

**Local**:
The stack running on a developer machine: `docker-compose.dev.yml` services
plus the Apps and API running on the host.
_Avoid_: dev environment — `dev` is an integration branch, not a place anything
runs.

**Production**:
The VPS. The only deployed environment; the `test` and `prod` branches are
promotion gates, not environments.
_Avoid_: prod server, staging — no staging exists.

### Data about usage

**Telemetry**:
Traces, logs and metrics describing how the API behaves.
_Avoid_: monitoring, APM

**Analytics**:
Events describing what people do in an App.
_Avoid_: tracking, telemetry
