# Database

`packages/database`: schemas, services, access rules, Liquibase.

## Database Schema Quick Reference

Schema folder: `packages/database/prisma/schema/` (`schema.prisma`, `auth.prisma`, `image.prisma`, and one file per App under `apps/`: `apps/laura.prisma`). An App's services live in `src/features/apps/<app>/`. The seed (`src/features/seed/`, `pnpm db:seed`) writes only the real Admin (`DATABASE_SEED_ADMIN_*`), Admin in every App: Local holds what Production holds. The Fixtures (`src/features/seed/fixtures/`: `FIXTURE.USER`, `FIXTURE.PASSWORD`, `FIXTURE.IMAGE`) go only into the Test template; `pnpm --filter @allonfire/storage image:setup` gives the Local `image` bucket what Production's `storage-setup` gives it (the bucket, closed: no policy, no Images).
Changelog: `packages/database/changelog/changesets/` — Liquibase owns every change (ADR 0008).

- **`auth` schema (shared):** `User`, `Membership`, `Session`, `Account`, `Verification`, enums `Role`, `App`
- **`image` schema (shared):** `Image` and `ImageApp`: the Images every App shows, each placed in one or more Apps (ADR 0013, ADR 0020), public or private as a whole (`Image.access`, `ImageAccess`, private by default; ADR 0027)
- **`laura` schema:** `GameScore`, enum `GameType`
- Change a model: edit the `.prisma` file, `pnpm db:changeset <name>`, review the SQL, `pnpm db:update`, `pnpm db:drift`. Never `prisma db push` or `prisma migrate`. Never edit an applied changeset.
- Services import per file: `@allonfire/database/features/image/image.service`, `@allonfire/database/features/apps/laura/game-score.service`, `@allonfire/database/features/auth/user.service` (`listUsers`, `createUser(user, hashedPassword)`: the User, a `credential` Account and their Memberships in one transaction, the email lowercased, a taken one `EmailTakenError`; `deleteUsers(ids)`: the cascades remove Memberships, Sessions, Accounts and Laura scores, Images keep with no uploader; `accessUserById(id)`: Memberships read now, never a cached Session's; `setUserImage(id, picture)`: the picture (`UserPicture`: the file's name and its blur, `User.imageBlurDataUrl`) set, or both cleared with null, and the file it replaced, in one transaction, null for an unknown User; `userImages(ids)`: the pictures those Users hold); the root exports only `prisma` and generated types. Enum values (`Role.VIEWER`, `App.LAURA`) come from `@allonfire/database/enums`; never copy an enum into a constant. A User's Role is per App, one `Membership` row per User and App (ADR 0019). Every rule about them lives beside them in `@allonfire/database/features/auth/access`: the schemas (`roleSchema`, `appSchema`, `App`), `ACCESS.ROLE_RANK`, `ACCESS.APP_SETTINGS` and `AppSettings` (`constants/access` and `constants/app-settings`: each App's `minRole`, `registration` and `indexing`), `AccessUser`, and `hasRole`, `roleIn`, `hasRoleIn(user, app, min)` (at least `min` in that App), `canEnterApp(user, app)` (a Membership in the App whose Role reaches its floor), `entryRoles(app)` (the Roles that reach its floor, what a form offers), `ImageVisibility`, `canSeeImage(user, { access, apps })` (public, or private and in an App the User enters; `user` null for a visitor), `canManageImage(user, app)` (Admin in that App), `canManageEverywhere(user, apps)` (Admin in every App the Image is in: its alt, its access, deleting it everywhere), `enterableApps(user)`, `accessUserFrom` (Memberships read as strings, narrowed). Never `z.enum(Role)` or a Role check by hand; an App declares its floor and Registration only in `ACCESS.APP_SETTINGS`.
- Adding an App to `App`: its changeset also inserts an `ADMIN` Membership in it for every Back Office Admin (`INSERT INTO auth."Membership" ("userId", app, role) SELECT "userId", '<new>', 'ADMIN' FROM auth."Membership" WHERE app = 'back-office' AND role = 'ADMIN'`), and the App gets its row in `ACCESS.APP_SETTINGS`.
- Raw SQL names the schema: `image."Image"`.
- Liquibase runs only in Docker (the `db-migrate` image, `packages/database/liquibase/`); Production runs `backup` then `deploy` before the Apps start.
