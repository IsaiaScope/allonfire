# Stored pictures

Images and Avatars: storage, the image server, signed links, how a page shows them (ADR 0027).

- Every stored picture (Images and Avatars) sits in the `image` bucket, closed: nobody reads it anonymously. It reaches a browser only through the `image-cache` service (nginx: keeps each answer, keyed on the whole link plus the format `Accept` picks, and serves it again only after asking imgproxy with its ETag once it is over a second old: imgproxy checks the link and the file, 304 without resizing, 404 once expired or deleted, so a dead link dies within `IMAGE_SERVER.CACHE_CHECK_SECONDS`; its config is inline in both compose files, kept identical by `service-names.test.ts`, since Production mounts no file) in front of the `image-server` service (imgproxy, `IMGPROXY_KEY`/`_SALT` from `STORAGE_IMAGE_SERVER_KEY`/`_SALT`; it reads only `s3://image/`, `IMGPROXY_ALLOWED_SOURCES`, Local also a test run's `allonfire-test-` buckets; Production at `https://${IMAGE_SERVER_HOST}`), by links the API signs (`@allonfire/storage/features/image-server/sign`: `pictureLink`, `pictureSrcSet`, `privateLinkExpiry`): a public Image's never expire; a private Image's and an Avatar's expire at the end of the hour after the next (`ceil(now / 1h) * 1h + 1h`), and only those the API lets see the picture get them. A public Image made private moves to a new file, so its public links die at once; one another request makes public meanwhile answers 409 `IMAGE_CHANGED` rather than turn private in place. The User module's `PUT`/`DELETE /users/:id/avatar` set and remove an Avatar; `User.image` holds its file's name (`avatar-<userId>-<uuid>.avif`), signed on every read (the list, the Session's `customSession`), or a provider's `https://` picture as it is; Google's `overrideUserInfoOnSignIn` stays off. In a page, a stored picture uses its signed links, never the App's optimizer: an Image's through `srcSetLoader` (`@allonfire/ui/lib/image-server-loader`), an Avatar's one link `unoptimized` (a loader that ignores the width makes next/image warn), its blur through ui's `tileBlur` (`lib/tile-blur`: the data URL as the `placeholder` from 40 px, none under; never `placeholder="blur"` on a tile told a small `width`, which next/image's 20px SVG blur turns see-through); a provider's picture goes through the optimizer, allowed by auth's `withProviderPictures` (a new provider adds its host to `AUTH.PICTURE_HOSTS` first, or next/image refuses it and a dev page breaks).
