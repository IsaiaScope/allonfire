# Design system

`packages/design`, `packages/ui`, `packages/shadcn` and the Tailwind rewrite.

`packages/design` holds no components and no React (ADR 0011, ADR 0014, ADR 0022): only fonts, CSS, Markdown and constants. That is the Designs (`src/designs/<name>/`: `DESIGN.md`, `DESIGN.json`, `theme.css`, fonts), each App's `PRODUCT.md` and stylesheet (`src/apps/<app>/`), the Brand's constants and impeccable's state. Every component lives in an App, under `apps/<app>/src/features/<topic>/components/` using next-intl directly, or in `packages/ui` when Apps share it, the generated-image ones included (`AOFBrandLogo`, `AOFShareCard`). Build or edit any page directly in its App with `/aof-design`, never plain `/impeccable`. An App's `globals.css` imports `@allonfire/ui/styles/base.css`, then `@allonfire/design/apps/<app>/styles.css`; generated images also read the Brand (`brand/aof-monogram`, `brand/aof-logo`) and a Design's image fonts, colours and card look (`designs/<name>/image-fonts`, `image-colors`, `share-card-look`). `ui` depends on `design`, never the reverse. `pnpm design:sync` copies a Design into the Apps wearing it; CI runs `--check`.

`packages/shadcn` is written only by tools: run `npx shadcn@4.21.0 add <name>` from `apps/back-office` and it lands there, then `pnpm --filter @allonfire/shadcn canonicalize`, which rewrites the CLI's classes to their canonical Tailwind spelling (`rounded-[4px]` to `rounded-lg`, what the editor's `suggestCanonicalClasses` asks for) against the package's own theme, then runs core's `vendor:patch` (`features/vendor/vendor-patches.ts`), which reapplies the fixes the App needs in CLI-written files (`VENDOR_PATCHES`, each with its reason: `useIsMobile` reads `mql.matches`, because iOS reports the old `innerWidth` mid-turn and left the sidebar a drawer on a phone turned sideways). A patch whose code the CLI no longer writes fails the tool and core's test, never drops unseen. Never edit it by hand: a fix is a `VENDOR_PATCHES` entry. A registry other than shadcn's (DiceUI, React Bits) installs the same way; React Bits' items land when the CLI runs in `packages/shadcn` itself (`pnpm dlx shadcn@4.21.0 add <url>` there). A vendor file that is not strict TypeScript is never edited and never relaxes anyone else: it goes in a lenient tsconfig beside the components (`"files"`) and in the package tsconfig's `"exclude"`, then `pnpm --filter @allonfire/shadcn vendor:types` writes its `.d.ts` beside it (core's `vendor:types`, which writes one only for the files a lenient tsconfig names, never for what they import). `packages/shadcn/src/components/tsconfig.json` is not strict at all (React Bits' `GooeyNav.tsx`); `tsconfig.relaxed.json` is strict but for `exactOptionalPropertyTypes` and `noUnusedLocals` (shadcn's `calendar`, `faceted`, `scroll-area` and `sonner`), so a `.d.ts` keeps its `null`s. `check-types` checks each file under its lenient config; every importer reads the `.d.ts` (the components export's `types` condition, which falls back to the `.tsx` for every other component) and stays strict, as `packages/ui` and the Back Office do with no flag off. packages/ui's `shadcn-compat` test fails when a component is in no list, in two, or lacks its `.d.ts`; a shadcn update that breaks a strict flag in a component ui imports fails ui's `check-types`, and that file joins `tsconfig.relaxed.json`. React Bits' Gooey Nav is forked into ui as `AOFGooeyNav` (`features/form/gooey-nav/components/aof-gooey-nav`, engine in `features/form/gooey-nav/utils/`), strict and drawn in the Design's corners; the upstream `GooeyNav.tsx` stays only to diff a React Bits update against. The rewrite is core's (`features/tailwind/canonicalize.ts`, `pnpm --filter @allonfire/core tailwind:canonicalize --css <stylesheet> --dir <folder>...`, built on Tailwind's own engine: no lint plugin matches the editor, `oxlint-tailwindcss` skips every class whose compiled CSS differs in text, `p-[16px]` beside `p-4`), and it runs on every App's classes against its own theme: an App's `tailwind:canonicalize` script passes its `src/app/globals.css`, its `src` and ui's components; the pre-commit hook runs it on the staged files before Biome (root `lint-staged`, one line per App), CI runs each App's `tailwind:check`, and `pnpm static:fix` rewrites all of it (Biome's fixes, then the Back Office's `tailwind:fix`); a new App adds its line to `lint-staged` and the same three scripts. Laura joins once rebuilt (its stylesheet still imports a theme that no longer exists). AOF components live in `packages/ui`, the only package that imports `@allonfire/shadcn` (Biome enforces it). ui keeps the package layout: a component lives in the ui feature that reads it (`features/form/`, `features/data-table/`, `features/navigation/`, `features/image/`, `features/feedback/`, `features/theme/`, `features/query/`; a feature's own parts are sub-features, `features/form/avatar-field/`), and one that two ui features read, or a primitive with no feature of its own (button, badge, card, dialog, tooltip), sits in `shared/components/`. Each file read outside ui has its own export key. An AOF component is named with the `AOF` prefix, `AOFButton` in `packages/ui/src/shared/components/aof-button.tsx`, so it never reads as the shadcn one it wraps. ui draws every icon from Tabler (`@tabler/icons-react`); lucide-react is not used in AOF components. See ADR 0010.

A class list two components share (a skeleton and its live twin, a Japan Design kanji action) is one cva both read, never classes copied by hand: the Back Office's `kanjiAction` (`shared/components/brush-kanji`) carries the line's green as its `tone`. One meaning has one signage/kanji constant: an action's kanji that means the same everywhere (Back, Cancel, Retry) is the App's `ACTION_KANJI` (`shared/constants/action-kanji`), never a copy in each feature's signage; the same kanji with another meaning (Reset's 戻) keeps its own.

## Pointers

- Design mobile-first and check new colour pairs and states in both themes against WCAG AA. Example: `packages/design/src/designs/japan/tests/theme.test.ts`.
- Use `cva` for reusable class variants and `cn` for inline defaults; infer wrapper and nested-part props from their components. Example: `packages/ui/src/shared/components/aof-tooltip.tsx`.
- Use an animation library for coordinated layout and visibility changes; reserve CSS transitions for simple effects. See `.claude/skills/aof-design/SKILL.md`.
- For component-library surveys, follow `/aof-design` and show free options. See `.claude/skills/aof-design/SKILL.md`.
- Every list's table is ui's `AOFDataTable` (TanStack Table on shadcn's `table`, every label a prop, cards below `md`, one scroller per axis since iOS has no directional lock); DiceUI's data-table was rejected for its English-only footer: `packages/ui/src/features/data-table/components/aof-data-table.tsx`. (`docs/superpowers/specs/2026-10-28-phone-landscape-design.md`)
- Nothing in any App is drawn under a notch, a rounded corner or the home indicator, held either way. ui owns it, so an App built from ui is safe without extra work:
  - the edges are base.css's `--gutter-top/right/bottom/left`, the larger of `--page-gutter` (1.5rem) and that side's `env(safe-area-inset-*)`, real only under core's `AOFBaseViewport` (`viewport-fit=cover`). Backgrounds run under the insets; text and controls never do.
  - every page is an `AOFPage`, which pads itself to the gutters on every side and has no way to drop them. A page may raise one side (`pb-24`), never replace all of them with `p-*`.
  - the frame: `AOFSidebarProvider` sets `--frame-bar-height` and `--frame-inset-left` (the screen's left inset, `0px` once the docked sidebar is drawn and clears it, read from what is drawn, never from `useIsMobile`). `AOFSidebarInset` sets its pages' `--gutter-left` from that value, `AOFSidebarHeader` and `AOFFrameHeader` (`features/navigation/components/aof-frame-header`) grow by the top inset and stay level, and the phone drawer pads by the left inset.
  - what ui lays over the page stays inside the gutters: dialogs (`SAFE_AREA.CENTRED`, `shared/constants/safe-area.ts`, centred between the gutters and scrolling past them) and toasts (`AOFToaster`). A fixed part a new component adds does the same (`bottom-(--gutter-bottom)`). The body is never padded, because fixed parts ignore its padding.
  - the guard: every App's e2e has an `e2e/safe-area.spec.ts` on config's `tests/e2e/safe-area` (`appRoutes`, `notch`, `outsideSafeArea`, `SAFE_AREA.INSETS`). It visits every page `appRoutes` finds in `src/app`, a new one included, upright, sideways and turned after loading, on Chromium, and fails on any text or control past the safe area. A page whose path has a param fails until the spec's `ADDRESS` gives it an address. Example: `apps/back-office/e2e/safe-area.spec.ts`.
  - not covered yet: Base UI's floating menus (dropdown, select, tooltip) keep 5px from the screen's edge, not the gutters, because shadcn's wrappers do not pass `collisionPadding` through. They open from controls that already sit inside the gutters.
- The design package's layout, exports and `design:sync` flags: `packages/design/README.md`.
