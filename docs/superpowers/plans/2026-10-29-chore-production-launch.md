# Production Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put AllOnFire's new stack live on the VPS, in this order:
- purpose-named hostnames, and production telemetry;
- an empty production database with one Admin;
- Laura and the ticked leftovers removed;
- everything behind Cloudflare's proxy.

This plan runs **before** Quality Fixes A and B.

**Architecture:**
- **Repo work first, tests first:** the production env files and their script, the Back Office build cleanup, the compose additions.
- **Then the outside steps, in dependency order.** Each uses a CLI where one exists (`gh`, `hcloud`, SSH through `/hetzner-ssh`). Otherwise it is guided or driven through `/iso-browser` (Cloudflare, Dokploy, OpenObserve).
- **Every value comes from the local `.env.production` files, through one script** that never prints a value.
- **Every irreversible or outward step stops for the owner's yes.**

**Tech Stack:** Docker Compose on Dokploy, Traefik, Cloudflare DNS and proxy, Hetzner Cloud firewall (`hcloud`), GitHub Actions (`gh`), MinIO (`mc`), OpenObserve v1.0.3, Liquibase, bash, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-production-launch-design.md`

## Global Constraints

- **Before any outward step,** announce exactly what will change and ask the owner with `AskUserQuestion`. Proceed only on a yes. That covers a DNS change, a secret, a Dokploy edit, a firewall rule, a push to test or prod, a database drop, a delete, and the Traefik restart.
- **Never print, log or paste a secret value.**
  - Values move only through `packages/config/local/env-production.sh`, into `gh` or onto the clipboard.
  - Reading a `.env.production` with `cat`, `grep` or `Read` is forbidden. Use `env-production.sh keys`.
- **Never invent a value.** An empty key in a `.env.production` stops the step, and the owner is asked to fill it.
- **Repo changes:**
  - tests first, with a `// @module-tag` first line in every test;
  - after each task: `pnpm exec biome check --write <files>`, then `pnpm lint` and `pnpm check-types` clean;
  - no `biome-ignore`, `@ts-expect-error` or `@ts-ignore` added;
  - never commit. Task 6 stops for the owner to run `/iso-commit`.
- **The GitHub account is IsaiaScope.** Run `gh auth switch` if a call fails.
- **Dokploy stores env as one string.** Every edit is a read-modify-write that keeps every other key. Check the key set before and after.
- **Hostnames:**
  - new: `api.`, `cdn.` (image server), `observe.` (OpenObserve), `storage.` (was `minio.`), `board.` (was `multica.`), `workflow.` (was `n8n.`), all on `isaiariva.com`, all A records on `188.245.174.30`;
  - kept: `back-office.`;
  - removed: `laura.`, `minio.`, `multica.`, `n8n.`.
- **The production database is dropped and rebuilt empty** (owner's decision), then seeded with one Admin.
- **Laura is deleted with no backup** (owner's decision).
- **The production `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` names stay** in this plan. Plan B renames them.

## Review Focus

- **An address removed while something still uses it.** An old record is deleted only after a `curl` through the new name answers, and after `git grep` and the inventory show no remaining reference (Tasks 7 and 11).
- **One record left DNS-only on `188.245.174.30` after the proxy goes on**, which exposes the origin. Task 12 lists every record on that IP and asserts that each one is proxied.
- **The visitor's IP lost behind Cloudflare.** Task 12 proves that the API's rate-limit key is the caller's address, through the proxy, after the Traefik change.
- **Certificate renewal broken by the proxy.** Task 12 forces a renewal check, and falls back to DNS-01 when HTTP-01 fails.
- **A deploy that starts without a required value.** Task 5's `check` must report zero empty keys before Task 8's deploy.

- Test: `packages/config/local/tests/env-production.test.ts`

**Interfaces:**
- Produces: `env-production.sh <command> <file> [key] [target]` with four commands:
  - `keys <file>` prints the key names, one per line;
  - `check <file>` prints each empty key, and exits 1 when any key is empty;
  - `copy <file> <key>` puts the value on the macOS clipboard with `pbcopy` and prints `copied <key>`;
  - `gh-secret <file> <key> <env>` pipes the value to `gh secret set <key> --env <env>`.

  No command writes a value to stdout or stderr.
- Example keys, grouped by `# GitHub prod`, `# Dokploy AllOnFire`, `# OpenObserve`:
  - root: the Dokploy-wide `API_HOST`, `BACK_OFFICE_HOST`, `IMAGE_SERVER_HOST`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `OO_S3_ACCESS_KEY`, `OO_S3_SECRET_KEY`, `ZO_ROOT_USER_EMAIL`, `ZO_ROOT_USER_PASSWORD`, `DOKPLOY_API_KEY`;
  - api: `AUTH_SECRET`, `API_REDIS_URL`, `STORAGE_IMAGE_SERVER_KEY`, `STORAGE_IMAGE_SERVER_SALT`, `TELEMETRY_HEADERS`;
  - back-office: `NEXT_PUBLIC_API_URL`, `BACK_OFFICE_URL`, `TELEMETRY_HEADERS`;
  - database: `DATABASE_URL`, `DATABASE_SEED_ADMIN_EMAIL`, `DATABASE_SEED_ADMIN_NAME`, `DATABASE_SEED_ADMIN_PASSWORD`;
  - storage: whatever its production env schema requires.

  Read the schemas, don't guess the keys.
