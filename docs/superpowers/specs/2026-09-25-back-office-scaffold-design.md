# Back office scaffold + shadcn/AOF Design system split — design

Date: 2026-09-25
Status: approved in chat, grilled against CONTEXT.md and docs/adr

## Intent

allonfire needs its internal App, the **Back office** (`apps/back-office`), where
the family's content, users and data are managed. This plan builds only the empty
shell — the visual design comes later with the impeccable skill. At the same time
the Design system is reset: `@allonfire/shadcn` holds shadcn components exactly
as the CLI generates them, and `@allonfire/ui` is rebuilt to hold AOF components
composed on top, plus one Theme per App. See ADR 0010 and the terms in
`CONTEXT.md` (Back office, Design system, shadcn component, AOF component, Theme).

**Success looks like:** `pnpm dev` starts the Back office on port 3400, `/` renders
English, `/it` renders Italian, the AOF `Button` (wrapping the shadcn one) renders
with the Back office Theme, and the pre-commit gate (Biome + check-types + tests)
is green across the workspace.

## Decisions

| Question | Decision |
|---|---|
| Audience | Internal admins; an App like any other, entry via Allowed apps (later) |
| Name | `apps/back-office`, `@allonfire/back-office`, term **Back office** |
| Old `packages/ui` | Moved to `packages/ui-old`, untracked, out of the workspace (like `auth-old`) |
| `apps/laura` | Paused: out of the pnpm workspace; folder stays tracked |
| Auth | Out of scope — ADR 0009 (auth in the API) is not merged yet |
| shadcn primitives | Base UI (`--base base`, preset `base-nova`) |
| shadcn components | All (`shadcn add --all`) |
| App imports | AOF components only; Biome `noRestrictedImports` rejects `@allonfire/shadcn*` everywhere but `packages/ui` |
| Themes | In `@allonfire/ui`: `styles/base.css` shared + `styles/theme-<app>.css` per App |
| Locales | `en` (default) and `it`, `localePrefix: "as-needed"` — `/` English, `/it` Italian |
| Add-ons | cacheComponents, React Compiler, typedRoutes, nuqs, TanStack Query devtools |
| Library rule | Front-end runtime libraries must have >1M weekly npm downloads |
| Agent skills | vercel agent-skills (core + extras), Next.js official, shadcn official |

Versions at design time (latest stable): next 16.3.6, react 19.3.0, shadcn CLI
4.21.0, next-intl 4.14.7, @tanstack/react-query 5.103.2, tailwindcss 4.3.3,
nuqs 2.10.1, @t3-oss/env-nextjs 0.13.11. Every front-end runtime library named
here was checked at >1M weekly downloads (lowest: @t3-oss/env-nextjs ~2.2M).

## Section 1 — Packages

### `packages/ui-old` (reference only)

- `git mv packages/ui packages/ui-old`, then `git rm -r --cached packages/ui-old`.
- `.gitignore` gains `/packages/ui-old/`; `pnpm-workspace.yaml` gains
  `!packages/ui-old`; root `vitest.config.ts` projects gain `!packages/ui-old/**`.

### `apps/laura` (paused)

- `pnpm-workspace.yaml` gains `!apps/laura`; root vitest projects gain
  `!apps/laura/**`. Biome's existing laura override stays.
- Known breakage, documented not fixed: `docker:build:laura` and
  `docker/docker-compose.prod.yml` still reference laura.

### `packages/shadcn` — `@allonfire/shadcn`

- Generated by the shadcn CLI: `init --base base --preset base-nova`, then
  `add --all`. Never hand-edited; updated only by re-running the CLI.
- Layout: `src/components/*.tsx`, `src/hooks/*`, `src/lib/utils.ts`,
  `src/styles/globals.css` (base-nova tokens + `tw-animate-css`), own
  `components.json`.
- Exports: `./components/*`, `./hooks/*`, `./lib/*`, `./styles/*`.
- Dependencies: whatever `add --all` installs.
- Biome ignores `packages/shadcn/src/**`. `check-types` runs. No tests.

### `packages/ui` — `@allonfire/ui`

- Depends on `@allonfire/shadcn`.
- Exports `./components/*` (AOF components) and `./styles/*`.
- `src/styles/base.css` imports `@allonfire/shadcn/styles/globals.css` and holds
  the shared base layer. `src/styles/theme-back-office.css` is the Back office
  Theme — base-nova defaults for now; impeccable reshapes it later.
- First AOF component: `AOFButton` in `src/components/aof-button.tsx`, a thin wrapper over the
  shadcn `Button` (same props, re-exported variants). It proves the
  shadcn → ui → App chain and is where the first customisation will land.
- `vitest.config.ts` from the shared preset; one test: the AOF `Button` renders
  a `<button>` and forwards `variant`.

### Docs (done during grilling)

- `CONTEXT.md`: App updated; Back office, Design system, shadcn component, AOF
  component, Theme added.
- ADR `docs/adr/0010-shadcn-generated-aof-components-on-top.md`.

## Section 2 — `apps/back-office` — `@allonfire/back-office`

- Files written by hand (the plan carries each one) rather than generated by
  `create-next-app`, whose boilerplate would be deleted anyway; versions are the
  latest stable listed above. Repo conventions: `tsconfig` extends `@allonfire/config/typescript/nextjs.json`,
  vitest + Playwright configs from `@allonfire/config/tests`.
- `next.config.ts`: `cacheComponents: true`, `reactCompiler: true`
  (+ `babel-plugin-react-compiler`), `typedRoutes: true`,
  `transpilePackages: ["@allonfire/ui", "@allonfire/shadcn"]`,
  `output: "standalone"`, wrapped with `createNextIntlPlugin()`.
- **i18n:** next-intl, `[locale]` segment, `locales: ["en", "it"]`,
  `defaultLocale: "en"`, `localePrefix: "as-needed"`.
  `src/i18n/{routing,request,navigation}.ts`, `src/proxy.ts` (intl middleware
  only), `messages/{en,it}.json`. Key parity between locales is a vitest test
  rather than an `i18n:check` script (turbo's `i18n:check` inputs are API paths).
- **Env:** `src/env.ts` with `@t3-oss/env-nextjs` + zod; `NEXT_PUBLIC_API_URL`
  (default `http://localhost:3300`). Declared now, used later.
- **Data:** TanStack Query, official App Router pattern — `getQueryClient()`
  (new client per server request, browser singleton), `staleTime` 60s, dehydrate
  pending queries. Server components prefetch and wrap children in
  `HydrationBoundary`.
- **Providers** (client): `QueryClientProvider`, next-themes `ThemeProvider`,
  nuqs `NuqsAdapter`, `ReactQueryDevtools` lazy in development only.
- **Routes:** `[locale]/layout.tsx` (html/body, `NextIntlClientProvider`,
  Providers), `[locale]/page.tsx` (translated title + AOF `Button`),
  `[locale]/not-found.tsx`, `[locale]/[...rest]/page.tsx` (unknown paths → the
  localized 404), `[locale]/error.tsx`, `global-error.tsx`. No custom fonts:
  typography comes with the impeccable pass.
- **CSS:** `src/app/globals.css` imports `@allonfire/ui/styles/base.css` and
  `@allonfire/ui/styles/theme-back-office.css`, plus `@source` for
  `packages/ui/src` and `packages/shadcn/src`.
- **shadcn CLI from the App:** `components.json` aliases `ui` to
  `@allonfire/shadcn/components`, so `pnpm dlx shadcn add <x>` run in
  `apps/back-office` writes into the package (shadcn's documented monorepo flow).
  The Biome import rule still stops the App from importing it.
- Port 3400 (`next dev --port 3400`).

## Section 3 — Agent tooling, tests, dev wiring

### Skills (project level, pinned in `skills-lock.json`)

- `vercel-labs/agent-skills`: `vercel-react-best-practices`,
  `vercel-composition-patterns`, `web-design-guidelines`,
  `vercel-react-view-transitions`, `writing-guidelines`
- `vercel/next.js`: `next-dev-loop`, `next-cache-components-adoption`,
  `next-cache-components-optimizer`, `next-partial-prefetching-adoption`,
  `next-partial-prefetching-optimizer`
- `shadcn/ui`: `shadcn`, `migrate-radix-to-base`
- Installed into `.claude/skills/` next to `doc-gen`; `CLAUDE.md` lists them.

### MCP (`.mcp.json`, root)

- `shadcn` → `npx shadcn@latest mcp`
- `next-devtools` → `npx next-devtools-mcp@latest` (dev tool, not a runtime
  dependency; the >1M rule does not apply)

### Tests

- Back office vitest: `messages/en.json` and `messages/it.json` have identical
  key sets.
- Back office Playwright smoke (`test:e2e`): `/` shows the English title, `/it`
  the Italian one, the AOF button is visible, no console errors.
- `packages/ui` vitest: AOF `Button` test above.
- Gate: `pnpm check-types`, `pnpm test`, `pnpm biome check .` green.

### Dev

- Root `dev` script unchanged; turbo picks up the Back office's `dev` task.

## Out of scope

Auth and Allowed-apps gating, API calls, real pages, visual design (impeccable),
Dockerfile and deploy for the Back office, laura migration, laura's Docker build.
