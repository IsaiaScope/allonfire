# Quality fixes: from the scan report to a gated CI

## Intent

The quality scan (`docs/superpowers/specs/2026-10-29-quality-scan-report.md`)
kept 155 verified findings. The owner wants every one of them solved or
consciously accepted. Then knip and jscpd guard the repo in CI, so the same
problems cannot come back unnoticed.

## The three layers (as agreed with the owner)

Every finding in the report belongs to exactly one layer:

| Layer | What it is | How many | Gated by CI |
|---|---|---|---|
| 1 | The report's **Shortlist**: the 15 costliest findings | 15 | no, but fixed first |
| 2 | Findings **knip or jscpd also report**: dead exports, files and dependencies, copy-paste | the tool hits, outside the Shortlist | yes, once phase 2 ends |
| 3 | Findings **only a reader saw**: literals in tests, misleading names, comments that lie, plus the two "Rules outdated" rows and the 16 "Rules to write" | the rest | no; the new written rules cover them from then on |

The report gains a `layer` column on every table, so each row says which
phase fixes it.

## Two plans

- **Plan A**: phases 1 and 2. It ends with CI gating knip and jscpd.
- **Plan B**: phase 3, run later, whenever the owner chooses.

Both start on a **clean tree**. The owner runs them after the Edit User work
is committed, so the 28 findings in those files are fixed on committed code,
not alongside another session's edits.

## Plan A, phase 1: the Shortlist

These are fixed test-first. The numbers are the Shortlist's.

1. **storage-1**: `prepareAvatar` wraps sharp's decode errors the way
   `prepareImage` does, through one shared encode-and-wrap step. A truncated
   JPEG answers 415 `UNSUPPORTED_IMAGE`, not 500.
2. **cross-15, unified logging.** Every fallback that catches an error still
   returns its fallback (the visitor still sees sign-in) and now logs the
   error.
   - **One pino logger factory moves to `core`** (`features/logger`, beside
     the `LOG` constants).
     - The API builds its logger with it and keeps its OpenTelemetry export
       through `pino-opentelemetry-transport`.
     - The Back Office builds its server logger with it too: JSON, pretty in
       dev, and logs shipped to the same OpenTelemetry collector.
   - **The Back Office gets `src/instrumentation.ts`** (Next's convention):
     - `register()` starts the OpenTelemetry NodeSDK on the Node runtime only,
       through `instrumentation.node.ts` as Next's guide shows, so Next's own
       spans reach the collector;
     - `onRequestError` logs every uncaught server error through the shared
       logger.
   - **The Back Office reads its own OTLP env.** It gets an endpoint, headers
     and a service name with the same meaning as the API's
     `OTEL_EXPORTER_OTLP_*` / `OTEL_SERVICE_NAME`. The names follow the
     standard OpenTelemetry variables the API already uses. They go into its
     `.env.example`, the CI env and the prod compose.
   - **Browser-side fallbacks** (the service worker registration, HEIC
     conversion) call `reportError`.
   - **Reasoning:** the API logs every request it *receives*. The Back Office
     logs only what the API can never see: calls that never reached it,
     Next's own render, action and proxy errors, and Next-only work.
3. **storage-19**: `copiesForPrivate` uses `Promise.allSettled`, and every
   success is cleaned through `deleteLeftovers` when any part fails.
4. **database-12**: a batch that would leave an Image in no App throws its
   own coded error and answers 409, not 404.
5. **config-design-root-1**: config's turbo `test` inputs list every repo
   file its tests read.
6. **cross-7**: one set of standard CodedError factories (404, 403, 413) in
   core, used by every module.
7. **cross-1**: one shared test host for the HTTP modules, replacing the two
   copies.
8. **back-office-1 to 4**: Edit a User and Add a User share their FormData
   readers, schema rules and form fields under neutral names, not Add's.
9. **cross-2**: the `STORAGE_*` local test defaults are written once.
10. **cross-12**: every `package.json` export key that nothing outside its
    package imports is removed.
11. **cross-11** (owner reversed the deletion): the 36 shadcn components
    that nothing wraps **stay**, and so do their dependencies. Nothing in
    `packages/shadcn` is deleted or edited. Instead, `knip.jsonc` accepts them
    with the reason "generated by the shadcn CLI, kept so any can be wrapped
    without re-adding". ADR 0010 is unchanged.
12. **config-design-root-2**: `STORAGE_ENDPOINT` and `STORAGE_BUCKET` leave
    the Back Office build: the Dockerfile, deploy, CI, turbo and the
    Playwright build step, along with the comments that are now false.
13. **ui-2**: ui's own code type-checks with `exactOptionalPropertyTypes`
    and `noUnusedLocals` on, and its three hidden errors are fixed. Only
    shadcn's generated files are exempted.
14. **cross-9**: `UNIT` gains `MS_PER_HOUR` and `MS_PER_DAY`, and the

15. **cross-14**: every flat constant moves into its owner's object.

## Plan A, phase 2: the tool hits and the CI gate

**The four tool improvements:**
- **Production mode.** Real entry points are marked with `!`, test folders
  stay out of production mode, and a `knip:production` script finds code
  that only tests use.
- **jscpd** reports `absolute` paths.
- **jscpd also scans YAML** in `.github/` and `docker/`, so the six copied
  CI setup steps become one composite action.
- **knip false positives are silenced**, for example `next` unresolved in
  `packages/config/typescript/nextjs.json`.

**Every remaining hit** from `pnpm knip`, `pnpm knip:production` and
`pnpm dupes` is either:
- **fixed**: the export deleted or the copy merged; or
- **accepted** with a written reason:
  - knip: in the config, which becomes `knip.jsonc` so each ignore carries a
    comment;
  - jscpd: through `jscpd:ignore-start`/`-end` with a comment, or the
    config's ignore list.

**The CI gate:**
- `ci.yml` gains one quality job: `pnpm knip`, `pnpm knip:production` and
  `pnpm dupes`, with jscpd failing on any clone (`exitCode`).
- The job runs on every pull request, unfiltered by affected packages,
  since together the tools take seconds.
- Phase 2 ends when that job is green.

## Non-goals

- Laura and `packages/auth-old`/`ui-old`. Their broken imports stay listed
  under "Held only by Laura" for Laura's rebuild.
- New features, or design or taste changes to pages.
- Fixes beyond what a finding asks for.

## Anti-goals

- **A green CI bought with silent ignores.** Every accepted hit carries a
  reason a reader can disagree with.
- **One huge unreviewable diff.** Each Shortlist item and each phase-2
  group is its own task, with its own tests, so a reviewer can reject one
  and keep its neighbour.

## Constraints

- All repo rules (AGENTS.md) hold, tests first.
- **Every fix passes Biome (Ultracite) and TypeScript** (owner's rule).
  After each task, run `pnpm exec biome check --write` on the files it
  touched, then the repo-wide `pnpm lint` (Ultracite plus oxlint
  type-aware) and `pnpm check-types`. Both must be clean before the next
  task starts.
- **No `biome-ignore`, `@ts-expect-error` or `@ts-ignore`, ever** (owner's
  rule, no exceptions). A fix that can't pass Biome or TypeScript without
  one is reshaped until it can. knip and jscpd ignores are a separate
  matter: they are allowed only with a written reason.
- Any new npm dependency passes the 200k weekly-download rule. The
  OpenTelemetry packages the API already uses are reused.
- Never commit. The owner runs `/iso-commit`.
- The production database and Dokploy are never touched by the plans.

  goes once that page uses them.

  rejected.
- **Existing suppressions**:
  - The `@ts-expect-error` lines in type tests (`*.test-d.ts`,
    `access.test.ts`) stay. Each one *is* an assertion that a wrong call
    must not compile.
  - The only `biome-ignore`, the barrel in
    `packages/database/src/index.ts`, goes. database's root entry is
    replaced by direct export subpaths, and every importer of
    `@allonfire/database` is updated. This is part of Plan A, phase 2.

My calls (the owner can overrule):

- **Logger reach.** core exports one ready Next server logger, built by the
  shared factory from OpenTelemetry's standard `OTEL_*` variables. Both the
  Back Office and `packages/auth`'s Next helpers import it, because a
  package can't import an App. auth's tests capture its lines through the
  same capture stream the API's logger tests use.
- **Telemetry is mandatory** (owner's rule, replacing my earlier "optional" call).
  - The API and the Back Office require `OTEL_EXPORTER_OTLP_ENDPOINT` and
    `OTEL_EXPORTER_OTLP_HEADERS`.
  - Local, tests and CI fill them from the local OpenObserve. Tests never
    ship lines.
  - Production gets ADR 0006's `telemetry` OpenObserve service in
    `docker-compose.prod.yml`. Umami is not in scope.
  - The owner deploys that infrastructure and sets its Dokploy values before
    the plan step that makes the variables required.
- **The `STORAGE_ENDPOINT` GitHub secret** is deleted by Plan A itself, with
  `gh`, once no workflow reads it (owner's request).
- **Rules ride with their code.** Each of the 16 rules is written in the
  task that fixes the code it describes. So the rules for cross-15, cross-12,
  cross-7, storage-19, config-design-root-1, config-design-root-2 and the
  composite action land in Plan A, and the rest in Plan B.
- **Layers follow the final tool config.**
  - The `layer` column is set after phase 2's tool improvements are
    configured: production mode, YAML scanning, the false positives
    silenced.
  - A finding the tools flag **in part** moves **whole** into Plan A, so
    no finding is ever half fixed by the gate.
- **Laura-only exports** (`playwrightConfig`, `formatErrorMessage`, the
  `game-score.service` key) are kept, never deleted. Each is accepted in
  `knip.jsonc` with the reason "held only by Laura".
- **In-progress findings get a re-check first.** Each task that touches the
  Edit User files starts by re-reading them. Any part already resolved
  (for example `user-form-data.ts`, `user-form-schema.ts` and
  `USERS.AVATAR_REMOVED` already exist) is ticked off, not redone.
